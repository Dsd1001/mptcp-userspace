基础设置

定义这份客户端 Profile 的运行方式与本地入口。

Relay 路径

每个 Profile 独立维护 2–8 条 Relay。复制会原样复制端口与带宽，并自动选中 IPv4 最后一段。

Scheduler

决定 MPX/4 Session 如何使用当前 Profile 的 Relay。具体路径评分仍由运行端实时状态决定。

Auto根据 Session 与 Carrier 状态自动选择运行策略。
Aggregate多条 eligible Carrier 并发承担普通流量。
Protect保留备用路径用于保护、恢复和重传。
Weighted将配置容量与 RTT、queue、penalty、delivery 等实时信号结合。

Transport Key

MPX/4 Userspace 的认证根凭据。默认隐藏，避免屏幕共享或截图泄露。

Client API URL

随机 Secret 始终保留。自定义模式只让 URL 增加一个可读标识，不会降低 bearer credential 的随机强度。

小写字母、数字、-、_；修改后会自动轮换 Secret。
切换 URL 模式或修改自定义标识会自动生成新的随机 Secret，旧 URL 立即失效且不会在将来重新生效。单独“轮换 Secret”不会改变自定义标识。

危险操作

删除 Profile 后，对应 Client API URL 会立即失效。

修改管理员密码

修改后台 Basic Auth 登录密码。新密码至少 24 个字符，修改成功后旧密码立即失效，并在服务重启后继续生效。

密码只写入 Provisioning 的私有 0600 密码文件，不会写进 Profile、浏览器存储或普通日志。环境变量中的初始密码仅作为首次启动/恢复时的 bootstrap fallback。

关于

MPX Provisioning 是配置/控制平面，不改变 MPX/4 数据平面协议。

Profile 数据文件包含 Transport Key 与 Client API Secret，应保持 0600 权限；反向代理应关闭或脱敏 /v1/config/ 的 access log。
